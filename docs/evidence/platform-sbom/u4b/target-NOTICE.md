# Notice

This file ships in the offline bundle, next to `THIRD_PARTY_NOTICES.md` (the
Python packages inside the `ke-app` image and the stack images, generated by
`scripts/bundle.sh` at bundle time) and `licenses/` (full licence texts).

Knowledge Engine is the code in this repository, built into the `ke-app` and
`ke-gateway` images and shipped as the scripts and configuration under `app/`
in the bundle. The Knowledge Engine is licensed under the MIT licence; the
full text is in `LICENSE` at the root of the bundle. Every third-party
component below keeps its own licence. Nothing in the bundle changes those
licences.

## Vendor images

Each third-party image in the stack is pinned by digest. A row here is the
reviewed licence for exactly that digest: `scripts/bundle.sh` reads this table
and refuses to write a bundle for a digest-pinned stack image that has no row
with a licence. Changing a digest in `docker-compose.yml` therefore needs the
licence checked again and this row updated. Keep each cell on one line and
never put a pipe character in one. The Licence cell must be an SPDX licence
identifier or expression, such as `GPL-3.0` or `BSD-3-Clause AND MIT`.

## Base image of `ke-gateway`

`docker/gateway.Dockerfile` builds on
`nginxinc/nginx-unprivileged:1.28-alpine@sha256:7377697a821c131a924a7105fafbe7414db4e9fcc77a6f08f776f33f141ec3f8`
(nginx 1.28.2). The image packaging (`org.opencontainers.image.licenses`) is
Apache-2.0, from https://github.com/nginx/docker-nginx-unprivileged; nginx
itself is BSD-2-Clause (`/usr/share/licenses/nginx/COPYRIGHT` inside the
image). `ke-gateway` adds only configuration.

## Base image of `ke-neo4j`

`docker/neo4j.Dockerfile` builds `ke-neo4j` from
`neo4j:5-community@sha256:0a6e7aedf54a531f76286032d4365ead65b11cca05e4a15cdf23b8e53d6db02b`
(Neo4j Community 5.26.32) and removes `/var/lib/neo4j/products`. That
directory holds the fleet-management plugin, which is under a commercial
licence with Neo4j, Inc., and the GenAI plugin, which the stack does not use.
No other file is changed: the filesystem is otherwise the official image's,
flattened into one layer. Neo4j Community itself is unmodified and is licensed
under GPL-3.0 (`/var/lib/neo4j/LICENSE.txt` inside the image, GNU GPL version
3, Neo4j Sweden AB); the licence text is `licenses/GPL-3.0.txt`. Upstream
source: https://github.com/neo4j/neo4j (tag 5.26.32).

## Base of `ke-app`

The shipped stage of `docker/app.Dockerfile` is `runtime`, which the last
stage copies whole (`FROM scratch`, then `COPY --from=runtime / /`). It
builds on
`python:3.12-slim-bookworm@sha256:34386ef0cb081344d7ec1c103ba398e6e9f64e9ab3a1509accc92a4e24a07258`.
Besides `/opt/venv` and `/app` it holds:

- CPython 3.12 under `/usr/local`, under the Python License 2.0 (SPDX
  `Python-2.0`: the PSF licence stacked on the BeOpen, CNRI and CWI
  licences). `/usr/local/lib/python3.12/LICENSE.txt` inside the image holds
  that licence stack only. CPython also builds in third-party code under
  its own licences. CPython's own list of it (among them expat and
  libmpdec) is in `licenses/CPython-3.12-incorporated.txt`; the licence of
  the HACL* hash code (MIT) in `_md5`, `_sha1`, `_sha2` and `_sha3`, which
  that list omits, is in `licenses/CPython-3.12-HACL.txt`, and that code
  compiles in KaRaMeL headers (Copyright INRIA and Microsoft Corporation,
  Apache-2.0), whose notice is in `licenses/CPython-3.12-KaRaMeL.txt` and
  licence text in `licenses/Apache-2.0.txt`.
- The Debian 12 (bookworm) packages of the base image, each under its own
  licence in `/usr/share/doc/*/copyright` inside the image and, where the
  bundle carries one, in the image's SBOM.
- The Debian packages the shipped stage adds: `libpq5` 15.19-0+deb12u1 (the
  `LIBPQ_VERSION` pin), under the PostgreSQL licence, and what apt pulls in
  for it: `libldap-2.5-0`, `libsasl2-2` and `libsasl2-modules-db`, with their
  licences in `/usr/share/doc/*/copyright` (and the SBOM where the bundle
  carries one).

pip is not shipped: the shipped stage removes the base's pip and
`ensurepip`'s bundled pip wheel, so the image carries neither pip nor the
packages pip vendors.

uv is not shipped: it runs only in the `builder` stage, which does not ship.

## Source code

`THIRD_PARTY_NOTICES.md` says, in its "Source code" section, for each
GPL-family component whether its source is in `sources/` of this bundle.
A bundle whose `THIRD_PARTY_NOTICES.md` has no "Source code" section has
no `sources/`, so it does not itself provide the source that a
GPL-family licence requires.
